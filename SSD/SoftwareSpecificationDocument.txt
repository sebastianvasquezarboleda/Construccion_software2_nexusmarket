# SOFTWARE SPECIFICATION DOCUMENT (SSD)
# NEXUSMARKET

## 1. Modelos del dominio

### User
Representa a los usuarios de la plataforma.

Atributos:
- id
- fullName
- email
- documentNumber
- role
- status

Comportamientos:
- Activar usuario.
- Bloquear usuario.
- Consultar si está activo.

### Buyer
Representa al comprador asociado a un usuario.

Atributos:
- id
- userId
- mainAddress
- additionalAddresses
- commercialStatus

Comportamientos:
- Agregar dirección.
- Eliminar dirección.

### Seller
Representa al vendedor asociado a un usuario.

Atributos:
- id
- userId

### Warehouse
Representa una bodega donde se almacena inventario.

Atributos:
- id
- name
- type

### Product
Representa los productos disponibles en NexusMarket.

Atributos:
- id
- name
- description
- type
- variants
- status

Comportamientos:
- Publicar producto.
- Suspender producto.
- Descontinuar producto.
- Agregar variantes.
- Identificar si es físico o digital.

### Inventory
Representa la cantidad disponible de un producto en una bodega.

Atributos:
- id
- productId
- warehouseId
- quantity

Comportamientos:
- Agregar inventario.
- Reservar inventario.
- Retirar inventario.
- Devolver inventario.
- Ajustar inventario.
- Consultar disponibilidad.

### Order
Representa un pedido realizado por un comprador.

Atributos:
- id
- buyerId
- items
- status
- total

Comportamientos:
- Agregar producto.
- Eliminar producto.
- Actualizar total.
- Enviar a pago.
- Marcar como pagado.
- Despachar.
- Finalizar.

## 3. Reglas de dominio implementadas

- Los campos obligatorios deben estar presentes.
- Los roles, estados y tipos deben ser válidos.
- El inventario no puede ser negativo.
- No se puede reservar más inventario del disponible.
- Un pedido vacío no puede enviarse a pago.
- Un pedido debe respetar su transición de estados.
- Un pedido finalizado no puede modificarse.
- Un producto descontinuado no puede volver a publicarse.

## 4. Estructura actual

La aplicacion sigue una organizacion hexagonal por capas:

- `application/domain/models/`: entidades y reglas del dominio.
- `application/domain/enums/`: enumeraciones del dominio.
- `application/domain/ports/out/`: puertos de salida que definen las operaciones de persistencia.
- `application/services/`: servicios de aplicacion que coordinan casos de uso.
- `application/adapters/out/persistence/document/`: documentos MongoDB.
- `application/adapters/out/persistence/repository/`: interfaces Spring Data MongoDB.
- `application/adapters/out/persistence/`: adaptadores MongoDB que implementan los puertos.
- `application/adapters/out/memory/`: adaptadores en memoria usados por pruebas unitarias.
- `src/test/java/`: pruebas de dominio, servicios y adaptadores.

MongoDB se configura mediante `MONGODB_URI`; las pruebas de integracion usan
`MONGODB_TEST_URI` y estan desactivadas por defecto. Las reglas principales
permanecen en los modelos de dominio y no dependen de MongoDB.
